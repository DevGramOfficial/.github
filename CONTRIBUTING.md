# Участие в разработке

Спасибо за желание помочь DevGram.

1. Перед изменением проверьте существующие issues и документацию.
2. Создайте отдельную ветку с коротким понятным названием.
3. Не смешивайте функциональные изменения с массовым форматированием.
4. Проверьте сборку или тесты затронутого проекта.
5. В pull request опишите проблему, решение и способ проверки.

Для плагинов используйте [DevGram Builder](https://github.com/DevGramOfficial/DevGramBuilder)
и [документацию SDK](https://docs.devgram.space/docs/introduction).

Сообщения об уязвимостях нельзя публиковать в открытых issues — следуйте
[правилам безопасности](SECURITY.md).
